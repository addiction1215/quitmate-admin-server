[[notice-create]]
=== 공지사항 생성

공지를 등록하면 공지 유형에 따라 앱 푸시를 보냅니다.

* 안내(`NOTICE`)·업데이트(`FEATURE_UPDATE`)·점검(`SERVICE_CHECK`): 알림 설정의 서비스 소식이 켜진 사용자
* 이벤트(`EVENT`): 광고성 앱 푸시 수신에 동의한 사용자만. 제목 앞에 `(광고)`, 본문 끝에 전송자(`이정현(엘제이에이치)`)·연락처와 수신 거부 방법을 붙입니다.
* 야간(21:00~08:00)에 등록한 이벤트 공지는 공지만 등록하고 푸시는 보내지 않습니다. 이때 응답의 `pushSkipReason` 에 까닭을 담습니다.
* 푸시 data 의 `notice_id` 에 공지 ID 를 넣습니다.

서식 본문(`contentHtml`)은 허용 태그만 남기고 정리해 저장하며, `content` 는 그 글자 버전으로 서버가 채웁니다.

* 허용 태그: `h2, h3, p, br, strong, b, em, ul, ol, li, table, thead, tbody, tr, th, td, a, img`
* 허용 속성: `a[href]`(http/https만, `rel="noopener noreferrer"` 자동), `img[data-key, alt]`, `th·td[colspan, rowspan]`
* `data-key` 가 `notice/` 로 시작하지 않는 img(외부 주소 포함)는 지웁니다. style·스크립트·이벤트 속성도 지웁니다.
* `contentHtml` 없이 `content` 만 보내는 옛 방식도 그대로 동작합니다.
