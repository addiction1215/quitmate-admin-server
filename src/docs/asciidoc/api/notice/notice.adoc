[[notice-list]]
=== 공지사항 목록 조회

공지마다 푸시 발송 상태(`pushStatus`)와 보낼 시각·보낸 시각을 함께 돌려줍니다.

[cols="1,3"]
|===
|pushStatus |뜻

|`DEFERRED` |발송 예정. 야간(20:00~08:00)에 등록한 이벤트 공지로, `pushScheduledAt`(다음 08:00) 이후 서버가 보냅니다.
|`SENDING` |발송 중
|`SENT` |발송함. 등록하며 바로 보냈거나, 보류했다가 보냈습니다.
|`FAILED` |발송 실패. 보내다 오류가 났거나 서버가 멈춰 끝을 확인하지 못했습니다. 일부에게 이미 갔을 수 있어 다시 보내지 않습니다.
|`CANCELED` |보내기 전에 공지를 지워 보내지 않았습니다(삭제한 공지는 목록에 나오지 않습니다).
|`null` |이 칸이 생기기 전에 등록한 공지
|===

[[notice-create]]
=== 공지사항 생성

공지를 등록하면 공지 유형에 따라 앱 푸시를 보냅니다.

* 안내(`NOTICE`)·업데이트(`FEATURE_UPDATE`)·점검(`SERVICE_CHECK`): 알림 설정의 서비스 소식이 켜진 사용자
* 이벤트(`EVENT`): 광고성 앱 푸시 수신에 동의한 사용자만. 제목 앞에 `(광고)`, 본문 끝에 전송자와 수신 거부 방법을 붙입니다.
* 야간(한국 시각 20:00~08:00)에 등록한 이벤트 공지는 공지만 바로 등록하고, 푸시는 다음 08:00 이후 서버가 보냅니다(`pushStatus` = `DEFERRED`).
  응답의 `pushSkipReason` 에 까닭을, `pushScheduledAt` 에 보낼 시각을 담습니다.
** 보낼 때의 최신 제목·내용·유형으로 보내고, 대상도 그때 다시 뽑습니다(그사이 광고 푸시 동의를 철회한 사람은 빠집니다).
** 보내기 전에 공지를 지우면 보내지 않습니다(`CANCELED`). 이벤트가 아닌 유형으로 고치면 08:00에 그 유형의 대상·문구로 보냅니다.
* 안내·업데이트·점검 공지는 야간에도 바로 보냅니다.
* 푸시 data 의 `notice_id` 에 공지 ID 를 넣습니다.
